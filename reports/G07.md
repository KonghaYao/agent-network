## 最终行为与变更

### 1. 持久模型

- `migrations/0025_group_history_boundary.sql`：
  - `room_members.member_generation INTEGER NOT NULL DEFAULT 1`；新建成员从 1 开始，非 active 成员重新加入时递增。
  - `rooms.member_history_policy`（`from_join` 默认 / `full`）、`member_join_policy`（`open` 默认 / `approval`）、`member_profile_policy`（`owner_admin` 默认 / `members`）、`member_mention_all_policy`（`owner_admin` 默认 / `members`）。
  - `room_files.created_seq`、`room_tasks.created_seq` 与 `(room_id, created_seq)` 索引；新写入以事件序号为准，升级前旧行保持 `NULL` 并回退 `created_at`，避免既有成员因升级突然失去旧内容。
  - `UPDATE room_members SET last_read_seq = MAX(last_read_seq, joined_seq)`：加入前内容不计入新成员未读。
- 本迁移不新增 guard；策略版本仍由既有 `guard_policy_revision` 裁决，成员代次只影响读取范围，不参与写事务版本竞争。
- 历史边界由 `src/domain/room-history.ts` 统一计算，direct 房间恒为全历史；group 的 `from_join` 使用 `joined_seq`（消息/事件/时间线）与 `joined_at`（文件/任务回退）。

### 2. 历史边界、成员代次与读取路径

- `historyBoundary(room, member)` 返回 `{ full, fromSeq, fromAt, policyRevision, memberGeneration }`；`historyCursorScope`/`decodeHistoryCursor` 把 history、timeline、search、files 游标绑定到 `room:<id>:<kind>:g<generation>`。
- 游标语义：同一视图的旧代次、无代次旧格式与 `room_files:<roomId>` 旧文件游标返回 `CURSOR_EXPIRED`；跨视图（如 messages 游标传给 timeline）仍是 `INVALID_ARGUMENT`，客户端不会把参数错误误判为需要重新翻页。
- 以下路径共用同一判定，过滤列表与按 ID 直读都不会绕过：
  - `network_history_list` 的消息与 timeline 共用一次边界与同一份 `authorization` 快照；
  - `network_message_read`、引用回复的父消息/被回复消息解析，边界外返回 `NOT_FOUND`；
  - `network_sync` 房间地板取 `max(events_min_seq, fromSeq)`，不补发加入前事件；
  - `network_rooms_list` / `network_room_get` 隐藏不可见的最后消息，返回 `my_member_generation`、`history_from_seq` 与 `authorization`；
  - 任务列表、概览与 `login.task_summary` 计数按 `created_seq`/`created_at` 过滤；claim/complete/fail/update/delete 对边界外任务返回 `NOT_FOUND`，材料失权后不能误验收；
  - 房间文件 list/get 使用同一 `createdHistoryFilter`/`visibleCreated`，边界外按 ID 直读返回 `FILE_UNAVAILABLE`；
  - `/f/<fileId>` 下载按票据中的 `member_generation` 与当前 active 成员资格、当前策略重新计算边界，失败返回 404。
- 重新加入路径（`roomMembersUpdate` 添加非 active 成员、`roomInviteRespond` 接受邀请）在同一事务内递增 `member_generation`、写入新的 `joined_seq` 并把 `last_read_seq` 重置到新加入点；房间视图的未读水位取 `max(last_read_seq, joined_seq)`。旧代次的游标、未读水位、排序位置与文件票据都不继承。
- 并发读取每次都从当前 `rooms`/`room_members` 行计算边界，并在结果中返回同一份 `authorization`；策略修改与并发读取只会看到提交前或提交后的同一版本，不会出现“列表按新策略、按 ID 直读按旧策略”的混合快照（G07-T03 覆盖）。

### 3. 策略、能力与影响提示

- `network_room_policy_set` 仅群主（`manage_policy`）可调用；必须带 `expected_policy_revision`，在单个事务内更新发言、邀请、任务、历史、入群审批、资料编辑与 `@所有人` 共 7 项策略，递增 `policy_revision`、写 `policy_updated` 审计并返回新的 `policy_impact`。
- `policy_impact` 字段：`history_policy`、`affected_members`、`hidden_tasks`、`hidden_files`、`material_loss`、`message`。收紧为 `from_join` 时统计会被隐藏的任务/文件并给出材料失权提示；开启 `full` 时提示已复制内容无法回收。
- 策略收紧后下一次读取立即生效：加入前消息、任务、文件、搜索摘要与引用预览按边界拒绝；任务完成/失败被拒绝；已签发文件链接与票据立即 404；已经复制或转发到外部的正文/文件无法收回。
- `src/domain/room-access.ts` 新增 `mention_all` 能力：direct 恒可用；group 默认仅 owner/admin，`member_mention_all_policy = members` 时放开。`network_message_send` 检测正文 `@所有人`，在发送事务内用 `capabilityGuardStatement(..., 'mention_all')` 复核；`@所有人` 只发提醒，不创建 delivery，也不被当作名为“所有人”的 Agent 参与 mention 解析。
- `member_join_policy` 与 `member_profile_policy` 已持久化、版本化并在 `room_get` 返回；审批强制执行属于 G02 依赖、资料编辑强制执行属于 G04 依赖，本次不重复实现（见限制）。

### 4. 管理记录

- 继续使用追加写的 `room_management_audit` 与 owner/admin 的 `network_room_role_history` 作为详细记录；详细记录包含动作、目标、操作者与版本，不包含消息正文或凭据。
- 新增 `network_room_notice_list { room_id, cursor?, limit? }`（`src/domain/room-notices.ts`）：只允许 active 成员，只返回影响调用者自身的事件（加入、移除、离群、任免、群主转让目标）以及 `policy_updated` / `announcement_updated`；使用固定 `summary` 取代原始 detail，不返回 `request_id`、版本、内部字段或正文。普通成员调用 `network_room_role_history` 返回 `PERMISSION_DENIED`。游标为 `room_notices:<roomId>:<caller>`，旧游标返回 `CURSOR_EXPIRED`。

### 5. 文件与票据

- `src/domain/file-ticket.ts` 使用 HMAC-SHA256 签发短时 `?t=` 票据，载荷含 `fileId`、`roomId`、`actorId`、`memberGeneration`、`expiresAt`，TTL 为 `LIMITS.fileTicketTtlMs`（1 小时）。
- 密钥来自 `FILE_TICKET_SECRET`；未配置时使用进程级随机密钥，进程重启后旧票据全部失效。多实例部署必须配置同一值。
- 未绑定上传保持公开语义；`network_room_file_bind` 后裸 `public_url` 立即 404，bind/get/list 返回带票据的 `preview_url` / `download_url`。每次下载都重新校验 active 成员、成员代次与历史边界，成员移出、重新加入的新代次、策略收紧或删除文件后返回 404。
- 网页 `src/web/chat-message-files-script.ts` 在裸 URL HEAD 失败后用当前房间调用 `network_room_file_get` 换取票据并重试，票据缓存 55 分钟；404 时丢弃票据重新换取。`src/web/chat-upload-script.ts` 的待发送 chip 同样使用票据地址，不再把公开 URL 写入草稿。

### 6. 工具、输出与验收

- 新增 `network_room_notice_list`；工具总数 80 → 81（关闭 Drive 75 → 76）。README、`docs/code-index.md`、主技能/静态技能、ChatGPT 指南与协议断言同步。
- 输出 schema：`memberSchema.member_generation`、`roomSchema.my_member_generation`/`history_from_seq`/`authorization`/4 项新策略、`roomCapabilities.mention_all`、`roomPolicyImpactSchema`、`roomNoticePageSchema`、history/task/file 的 `authorization` 快照。
- `scripts/lib/group-history-acceptance.ts` 与 `scripts/lib/group-policy-acceptance.ts` 由 `scripts/acceptance.ts` 在 G03/G05/G01 之后执行；`scripts/verify-web.ts` 更新文件卡片票据、HEAD 次数与坏图拦截断言；`scripts/verify-protocol.ts` 更新工具/技能摘要；`scripts/lib/feedback-unit.ts` 覆盖 `0025` 的旧库升级。
- 网页仅新增/调整文件卡片与上传 chip 的票据链路；策略编辑与通知列表暂未提供网页入口（见限制）。

## 契约、权限与数据变化

- **迁移**：仅新增前向迁移 `0025_group_history_boundary.sql`，未修改既有迁移；新库按序应用、旧库升级由 `feedback-unit` 覆盖，旧任务/文件行通过 `created_seq IS NULL` 回退 `created_at` 保留既有成员可见性。
- **新 guard**：无。策略版本继续使用 `guard_policy_revision`；成员代次不新增写闸门。
- **工具**：新增 1 个 `network_room_notice_list`；总数 80 → 81（关闭 Drive 75 → 76）。
- **输出 schema**：新增 `authorization` 快照、`member_generation`、`history_from_seq`、4 项策略、`mention_all` 能力、`policy_impact`、通知页；history 页的 `authorization` 为可选字段，兼容旧客户端。
- **权限**：群主策略修改、owner/admin 详细审计、普通成员脱敏摘要、`@所有人` 能力与文件票据下载都按当前成员/代次/策略判定；群角色与所有权模型不变。
- **数据与链接**：绑定文件的下载从“公开 URL”改为“短时票据”；未绑定上传保持公开。票据密钥、TTL 与多实例要求已写入 README 部署章节。
- **事件**：策略与公告变更继续写既有 room scope 事件与 `room.membership` informational 项；`@所有人` 只作为消息正文，不创建 delivery、不增加 `pending_count`、不推进 `head_seq`。管理摘要读取不写 events/outbox。

## 问题与限制

1. **搜索、收藏、转发与引用预览入口依赖后续任务**：本仓库当前没有 M04/M05/M08 的搜索、收藏、转发工具，因此无法端到端验证这些入口；`room-history.ts` 已预留 `search` 游标种类，房间摘要、引用父消息、按 ID 直读、任务上下文、文件列表/下载已全部按同一边界实现。后续任务接入时必须复用 `historyBoundary`，不得另写过滤。
2. **入群审批与资料编辑只完成持久化**：`member_join_policy = approval` 与 `member_profile_policy` 已版本化、返回并参与能力快照，但审批队列属于 G02、资料编辑强制执行属于 G04；本次未重复实现，不能视为审批/资料编辑已端到端支持。
3. **网页没有策略编辑与通知入口**：`network_room_policy_set` 与 `network_room_notice_list` 仅通过 MCP 提供；网页已有的房间/消息/文件读取都走同一服务端边界，但没有可视化策略修改或“影响我的管理事件”列表。若产品要求网页可管理，应另开任务补 UI。
4. **已复制内容无法回收**：票据、游标与列表在撤权后立即失效，但用户已下载/转发的正文与文件字节无法由服务端召回；这是任务明确接受的边界，界面与技能正文均如实说明。
5. **未绑定上传仍是公开的**：未绑定文件可按公开上传语义访问，只有 bind 后才纳入房间成员、代次与历史边界。该语义沿用 M07 之前的产品选择；若要求“上传即私有”，需要 M07 调整上传模型。
6. **票据密钥缺省为进程级随机**：未设置 `FILE_TICKET_SECRET` 时，进程重启使所有旧票据失效；多实例部署必须配置同一密钥，否则不同实例签发的票据无法互认。已写入 README。
7. **旧行的时间回退**：`room_files`/`room_tasks` 升级前没有 `created_seq`，只能按 `created_at` 与 `joined_at` 比较；同一毫秒的边界行可能按时间落入可见侧。新写入全部有 `created_seq`，不受影响。
8. **在线状态与投递状态不变**：成员代次只影响读取边界与文件票据，不改变 delivery 的 claim/complete/fail 语义；移出/重新加入不会自动取消既有 delivery，需由后续任务按产品要求处理。
