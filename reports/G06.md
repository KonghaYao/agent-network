## 最终行为与变更

### 1. 退群预览与在途工作

- 新增只读工具 `network_room_leave_preview { room_id }`，返回 `in_flight_tasks`（`task_id`、`title`、`status`、`owner_actor_id/name`、assignment 信息）、`pending_deliveries`、`claimed_deliveries`、`owner_transfer_required`、`can_leave`、`can_dissolve`、`dissolved`、`read_only`。
- `network_room_leave` 存在在途任务或 pending/claimed 投递时，未传 `confirm_in_flight: true` 返回 `CONFLICT`（details.reason=`in_flight_work`，附同一任务列表），不再静默丢失。确认后同一事务撤销任务执行资格与投递，并返回被撤销的任务列表。
- 网页退群先调用 preview，在确认框中列出 `task_id · status · owner`；群主未转移时提示先转让或解散。

### 2. 退群/移除的即时后果

- 退群与被移除均在同一事务把该成员任务执行资格撤销：`in_progress/blocked` → `blocked + owner_lost_eligibility`，尚未接受的 `offered` → `unassigned`；撤销 `offered/active` assignment、关闭 `task_offer/task_reminder` 的 pending/claimed delivery、取消 pending 交接。
- 复用并扩展 `revokeTaskEligibilityStatements`，没有复制任务状态机。被移除者旧 claim、旧任务提交、按 ID 读取任务/历史、旧文件票据立即失败；其其他群与身份保持正常。
- `member_left`、`member_removed` 写 room scope 事件与 `room:{id}` outbox，不创建 delivery、不增加 `pending_count`；成员变化改用 `roomMemberVersionStatement`，只推进 `member_seq`，不推进消息 `head_seq`。
- 文件绑定/删除/发布与消息发送在事务内增加 `guard_room_dissolved`；`/f` 下载继续由 M07/G07 实时鉴权，撤销成员资格后旧票据返回 404，已下载副本无法技术回收，页面不承诺收回。

### 3. 移除 × D04 接任并发

- 不新增第二套负责人状态：D04 的 task revision、assignment 状态与 `revokeTaskEligibilityStatements` 的条件更新共同裁决。
- 移除先提交：任务 blocked、owner 为空、assignment 撤销，旧接任提议不能接受；接任先提交：保留新 assignment 与新负责人，移除旧负责人不覆盖。
- 专项覆盖 10 轮 `Promise.allSettled` 并发（本轮实际 remove_won=10、transfer_won=0）与两种确定性顺序（先移除后接受失败、先接任后移除保留新指派）。

### 4. 解散（owner only）

- 新增 `network_room_dissolve { request_id, room_id, reason? }`。同一事务：
  - 取消所有未结束任务（`reason = room_dissolved`，不自动标记 accepted/completed），保留 `task_submissions`/`task_reviews` 审计；
  - 撤销所有 `offered/active/submitted` assignment 与 pending 交接；
  - 取消房间内 pending/claimed delivery，按当前 pending 行数递减 `pending_count`；
  - 撤销 pending 邀请（含链接）、入群申请与 pending owner 转让；
  - 写 `room_dissolved` room 事件与 outbox、`room_dissolved` 管理审计；`member_seq` 前进但 `head_seq` 不前进；
  - 设置 `dissolved_at/dissolved_by/dissolve_reason/archive_head_seq/archive_member_seq`，不删除任何业务行。
- 群主在任何未解散群都不能直接退群，即使只剩自己一人；必须先完成 G05 owner 转移或解散。遗留无主群（`owner_id IS NULL AND dissolved_at IS NULL`）只来自修复前的旧数据，禁止再邀请或加入成员，但不会自动解散、回填 owner 或硬删。

### 5. 只读归档与读取边界

- `HistoryBoundary` 增加 `toSeq/toAt`；消息、时间线、sync、房间最后消息、文件、任务、按 ID 直读与文件票据授权都应用 `archived_head_seq` 上界。解散事件本身作为归档事件高水位，sync 只在该上界内补读。
- 解散时仍 `active` 的成员保留只读归档；此前 `left/removed` 的成员没有归档资格。归档页允许读取解散前消息与文件（重新获取带票据地址），但拒绝发送、建任务、绑定/删除/发布文件、邀请、角色/策略/公告、owner 转移与再次解散。
- `network_room_get` / `network_rooms_list` 新增 `status`、`dissolved_at`、`dissolved_by`、`dissolve_reason`、`archived_head_seq`、`read_only`、`can_leave`、`can_dissolve`；`capabilities` 在归档中关闭写能力，保留 owner/admin 的审计读取。

### 6. 网页

- 群菜单新增“解散群聊”，仅 owner、未解散且非归档时显示；退群前展示在途任务与投递。
- 解散房间显示“群聊已解散，当前为只读归档…已下载副本无法收回”横幅，隐藏输入框、附件与新建任务入口，禁用文件上传；会话列表显示“已解散 · 只读归档”。

### 7. T04 通话依赖缺口

- 成员失权与解散事件 metadata 含 `media_revoke: true`，并携带 `room_id/actor_id/member_generation` 或取消任务摘要，作为未来 M09 媒体层的稳定撤权钩子。
- M09 通话模块尚未实现（P1），本任务没有媒体平面可终止，也没有新增假媒体实现。**不能声称已验证媒体发布/订阅终止**；T04 的媒体部分保持依赖缺口。

## 问题与限制

1. **T04 媒体终止是依赖缺口**：M09 通话模块未实现，本任务只提供 `media_revoke` 事件钩子，未验证也无法声称媒体发布/订阅被终止。
2. **并发覆盖规模**：G06 专项并发 10 轮，本轮实际只观察到 remove_won；两种提交顺序由确定性顺序测试补齐。未按通用矩阵要求跑 100 次固定种子调度，独立验证可复跑。
3. **普通上传与房间绑定分离**：`POST /mcp-upload` 仍可创建上传者私有草稿（不属于房间写入）；解散后绑定/发布/删除被拒绝，网页隐藏上传入口。
4. 已下载到本地或已被外部系统读取的文件副本无法技术回收；文档与 UI 均不承诺收回。
5. 归档读取以 `archived_head_seq` 截断事件/消息/文件/任务；解散后的邀请预览等只读元数据仍可能可查，但接受/批准等写操作被拒绝。
6. 旧文件票据在解散后继续有效（对仍 active 的合法成员），因为授权每次重新计算成员资格与归档边界；成员退出/被移除后立即 404。
7. **遗留无主群只做防御，不自动修复**：修复前的缺陷可能已在旧库留下 `owner_id IS NULL AND dissolved_at IS NULL` 的活跃群。修复后所有加人路径（定向邀请、邀请链接、邀请接受、入群申请批准、管理员添加）在预检查与事务 guard 双重拒绝，`room_get` 返回 `owner_missing=true`；但没有自动解散、回填 owner 或硬删，若旧群没有 active owner 行，当前版本没有工具可以人工解散，需要维护者在数据库层面决定归档或修复。详见 `reports/G06-FIX.md`。
8. **群主退群语义已收紧（2026-11-04 修复）**：独立验证发现旧实现只在“还有其他 active 成员”时要求转移 owner，owner 独自一人可以退群并留下无主群，旧邀请链接还能让外部用户加入。现在 `network_room_leave_preview` 对任何未解散群的 owner 返回 `can_leave=false`、`owner_transfer_required=true`，`network_room_leave` 一律返回 `CONFLICT`（reason=`owner_transfer_required`），事务 guard 按 `rooms.owner_id = caller AND dissolved_at IS NULL` 复核。G03/G01/G05/G06 依赖旧行为的用例已同步更新。
