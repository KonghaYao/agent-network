## 最终行为与变更

### 1. 上传即私有草稿

- `migrations/0026_private_files_retention.sql` 新增 `drive_files`：`owner_scope`、`uploader_id`、`state`（`draft`/`bound`/`deleted`）、`visibility`（默认 `private`）、`room_id`、`expires_at`（NULL 表示保留）、`retained`、`deleted_at/by`、`purged_at`。上传成功后登记为上传者私有草稿，草稿期 `LIMITS.fileDraftTtlMs = 24h`。
- `src/drive/service.ts` 的 `attachPublicUrl` 在 MCPP Files 返回 201 后登记 `drive_files`，保持 `publicUrl` 作为文件身份，同时返回带文件票据的 `previewUrl` / `downloadUrl`、`expiresAt`、`state`、`visibility`、`retained` 与当前配额。登记失败回收本次载荷并返回 503 `FILE_UNAVAILABLE`；草稿配额超限时标记本次上传 `deleted`、回收载荷、返回 507 `QUOTA_EXCEEDED`，不会把 10 年底层 TTL 当成无限空间。
- `registerDriveFile` 统一处理首次登记与旧库对齐：已有 `room_files` 的旧上传登记为 `bound`/`deleted` 并继承房间、`retained`、`expires_at`；`drive_file_info` 对旧库未登记文件在首次授权读取时补齐为私有草稿。迁移同时为已有 `room_files` 回填 `drive_files`，升级后旧裸 URL 一律收紧为私有。

### 2. 下载票据与逐次授权

- `src/domain/file-ticket.ts` 升级为 v2 HMAC 票据（base64url，`?t=`）：`{fileId, scope: 'room'|'file', subject, roomId, memberGeneration, policyRevision, expiresAt}`，TTL `LIMITS.fileTicketTtlMs = 60 分钟`；不携带长期 Bearer，浏览器 `<img>`/`<video>`/Range/下载链接都走同一地址。
- `src/domain/file-access.ts` 的 `authorizeFileDownload` 是 `/f` 唯一授权入口，统一 404，不区分“不存在/无票据/已撤权”：
  - 房间文件：票据 scope 必须是 `room`，每次重新读取房间与成员，校验成员仍 `active`、`member_generation` 一致、`rooms.policy_revision` 一致，并复用 `historyBoundary`/`visibleCreated` 判断文件在历史范围内。移除、退群、重新加入（代次递增）或策略收紧后旧票据立即失效。
  - 未绑定文件：只接受 scope `file` 且 `subject` 等于 MCPP `ownerScope` 的票据；旧库未登记文件同样要求上传身份的文件票据。
  - 显式公开（`drive_files.visibility = 'public'`）才允许裸 `/f/<fileId>`。
- `src/app.ts` 的 `/f` 在读取票据前先校验文件登记与过期时间；HEAD、`Range`、`if-none-match` 304、`?download=1` 与普通 GET 共用同一次授权，不会出现“GET 拦截而 HEAD/Range 绕过”。
- `network_room_file_get/list`、`drive_file_info`、消息文件卡片与图片预览均改为返回带票据地址；`public_url` 仍返回但默认不可读，保留“文件身份”语义。图片仍以受控 `previewUrl` 做 inline 预览，不新增公开缩略图端点。

### 3. 显式公开发布

- 新增 `network_file_publish { request_id, file_id, public, room_id? }`：默认关闭，已绑定房间的文件只有上传者或群 owner（direct 仅上传者）可操作，未绑定草稿只有上传者可以操作；`public` 为 `false` 时撤销发布。
- 发布不延长 TTL，公开文件仍受草稿 24h 或附件 30d 约束；撤销后裸 URL 立即 404，客户端重新调用 `network_room_file_get` 或 `drive_file_info` 获取带票据地址。发布/撤权与幂等操作在同一 `runIdempotent` 事务内完成。

### 4. 成果保留、引用与 GC

- 新增 `artifacts`（房间/任务/版本/文件/提交者/摘要/状态/`created_seq`）与 `file_references`（`task`/`artifact`/`forward`/`favorite` 四类，`active`/`released`）；唯一索引保证同一 `file_id` 只对应一个成果、同一任务版本不重复。
- `network_artifact_submit` 把当前身份自己的文件绑定到房间并提交成果版本：任务成果只允许任务创建者、当前执行者或群 owner；提交前在同一事务内检查房间文件数量/字节配额，超限整批回滚，不产生 artifact、引用、房间文件、事件、outbox、幂等记录或半成品任务状态。文件随即 `retained = 1`、`expires_at = NULL`，不再随 30 天附件 TTL 清理。
- `network_artifact_list` 按成员历史边界过滤、按提交时间倒序分页，可按 `task_id` 过滤，返回文件票据地址与房间配额；`network_artifact_release` 只释放成果自己的引用，仍被有效任务或其他成果引用时继续保留并返回 `retained: true`，否则恢复 30 天 TTL；释放幂等。
- `src/maintenance.ts` 的 `maintainFiles` 按引用可达性统一回收：先释放已删除任务的 task 引用，再恢复无引用的 `retained`，只对“无 active 引用、无 delivered 成果、未被 retained”的过期文件软删；软删后保留 `LIMITS.fileGcGraceMs = 7 天` 再删除载荷并写 `purged_at`，业务元数据永久保留。删除载荷前再次检查引用；`room_files` 墓碑删除放在释放与载荷回收之后，避免“先删行、后绑定”。
- 成果提交的 `INSERT ... ON CONFLICT(file_id) DO UPDATE SET retained = 1` 与 `guard_file_unavailable` 在同一事务内消除“读取后、提交前被 GC 删除”的竞态；GC 只会软删已过期且无引用的文件，已 `deleted` 的文件不能再被成果绑定，因此并发结果只能是“绑定成功并保留”或“明确失败”。

### 5. 契约、配额与文档

- 新增工具输入/输出 schema、错误映射与 `src/mcp/outputs.ts` 输出结构；工具只在启用 MCPP Files 时注册。
- 新阈值集中在 `src/contracts/limits.ts`：草稿 24h、附件 30d、GC 宽限 7d、每 actor 草稿 1 GiB / 500 个、成果页 20/100、摘要 1024 B、版本上限 1,000,000；`DRIVE_TTL_SECONDS` 默认调为 10 年，由业务 TTL 与 GC 治理。
- README、CLAUDE.md、`docs/code-index.md`、主技能与 harness 技能正文已同步实际行为，去掉了“服务端独立缩略图”的不实描述，并如实标注转发/收藏引用尚未由 M05/M08 写入。

## 契约、权限与数据变化

- **迁移**：`0026_private_files_retention.sql` 新增 `drive_files`、`artifacts`、`file_references`，给 `room_files` 增加 `retained`；新增 `guard_file_unavailable`、`guard_artifact_conflict`、`guard_file_referenced`，并同步 `GUARD_TABLES`/错误映射；回填已绑定 `room_files` 到 `drive_files`。
- **工具**：新增 `network_file_publish`、`network_artifact_submit`、`network_artifact_list`、`network_artifact_release`；`drive_file_info` 与房间文件输出新增 `previewUrl`/`downloadUrl`、`state`、`visibility`、`retained`、`quota` 等字段。写工具都要求 `request_id` 并走 `runIdempotent`。
- **权限**：房间文件读取 = active 成员 + 历史边界 + 票据中的成员代次/策略版本；发布 = 上传者或群 owner（direct 仅上传者）；成果提交 = 上传者本人文件 + 任务创建者/当前执行者/群 owner；释放 = 成果提交者、文件上传者或群 owner。
- **错误码**：不可下载统一 404；工具侧使用 `FILE_UNAVAILABLE`、`NOT_OWNER`、`NOT_FOUND`、`CONFLICT`、`VERSION_CONFLICT`、`ROOM_FILE_LIMIT`；上传草稿超配额使用 HTTP 507 `QUOTA_EXCEEDED`。
- **客户端影响**：`publicUrl` 不再是可直接分享的下载地址；需要展示文件时必须使用工具返回的 `previewUrl`/`downloadUrl`。显式发布后的裸 URL 才可长期分享。`FILE_TICKET_SECRET` 必须在同一部署的所有实例间共享，否则票据互不认可。

## 问题与限制

1. **无独立服务端缩略图端点**：需求中的“缩略图受控”通过受控 `previewUrl` 实现，客户端缩略图复用该地址，不新增公开缩略图路由。大图流量仍由客户端缓存策略控制。
2. **转发/收藏引用尚未写入**：`file_references` 已支持 `forward`/`favorite` 并参与可达性判断，但当前只有 `task`/`artifact` 引用有写入方；M05/M08 接入后自动参与保留，不需要再改 GC。
3. **已下载字节无法撤回**：撤权只阻止新的 `/f` 请求和票据复用；授权有效期内已经完成下载的字节无法收回，这是 HTTP 文件服务的固有限制。
4. **票据密钥运维**：未配置 `FILE_TICKET_SECRET` 时使用进程级随机密钥，进程重启后旧票据全部失效；多实例部署必须共享同一密钥，否则票据在实例间不可用。
5. **旧公开上传语义按 M07 要求收紧**：升级前可直接访问的裸 `/f` 链接不再可读，上传者需通过 `drive_file_info` 获取带票据地址，或显式 `network_file_publish`；这是任务第 3 条的预期变化，不是回归。
6. **验收环境依赖 presence 短窗口**：`test:acceptance` 的“关闭最后一个连接后成员显示离线”在默认 60s 活动 TTL/30s grace 下会超时（`reports/INTEGRATION.md`、`reports/BASELINE.md` §3.7 已记录）；本次按既有做法用 `AGENT_PRESENCE_ACTIVITY_TTL_MS=5000`、`AGENT_PRESENCE_GRACE_MS=2000`、`AGENT_PRESENCE_SWEEP_MS=1000` 运行，非 M07 代码回归。
7. **配额口径**：草稿配额按 `owner_scope` 只统计有效草稿；房间配额按 `room_files`（未删除且未过期或 retained）统计。缓存/已软删但未清理的字节不计入配额，但会在 GC 宽限期后回收。
