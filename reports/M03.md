## 最终行为与变更

### 1. 提及是持久模型，接收者来自明确选择（新增 + 复用）

- 新增迁移 `migrations/0028_message_mentions.sql`：`message_mentions(message_id, actor_id, actor_kind, source, created_at)`，主键 `(message_id, actor_id)` 保证同一消息对同一成员至多一行；`source ∈ explicit|text|all`，`idx_message_mentions_actor` 支持按成员补读。迁移同时建立 `guard_invalid_mention`，显式人类提及在发送事务内复核“仍是当前房间有效人类成员”。
- `network_message_send` 新增可选 `mentions: string[]`（人类 `actor_id`，去重后最多 `LIMITS.invokeMax = 8`）。语义分工固定：`invoke` 只接受 Agent，是唯一派活来源；`mentions` 只接受人类，是个人提醒，不创建 delivery、不改变 `pending_count`、不推进 `rooms.head_seq`，也不唤醒 Agent 的 inbox 提示。
- 消息视图（`network_history_list`、`network_message_read`、timeline 与 `mention_reminder` 流项）回读 `mentions: [{ actor_id, name, actor_kind, source }]`。事件侧新增 `mention_reminder`（`MCPEvents` 的 `mention.reminder`，informational，`mention_all` 标记），写入 recipient 的 inbox 事件与 outbox，但不写 `inbox:{actor}` 提示、不增加 `pending_count`。
- `source` 冲突按 `all < text < explicit` 归并；显式选择永远覆盖正文解析，正文解析覆盖 `@所有人`，因此同一输入在 Web、MCP、CLI 得到同一份提及集合。

### 2. 正文 @ 只作输入便利，解析规则确定（新增）

- 仅当请求**省略** `invoke`、房间为 group、且不是带 claim 的回复时才解析正文；显式 `invoke: []` 始终关闭派活，普通群回复、`final_body`、direct、claim 回复都不解析。
- `instructionText()` 只保留“指令正文”：去掉 Markdown 围栏代码块（未闭合围栏延续到文末）、行内代码、`>` 引用行和 `http(s)://` URL；这些位置出现的 `@名字` 不创建 delivery，也不记录提及。
- 匹配使用当前 `active` 成员名，区分大小写、按存储值精确匹配、最长名字优先；发送者自己、非成员、已移除成员不产生目标。唯一精确匹配写入 `source = text`。
- 两个及以上 Agent 同名时返回 `INVALID_ARGUMENT`，错误不回显成员名，并提示使用选择器或显式 `invoke`；该失败不推进房间 head、不改变任何 Agent 的 `pending_count`。正文解析目标超过 8 个同样 `INVALID_ARGUMENT`，不截断。
- `@所有人` 仅 `owner`/管理员（`mention_all` 能力）可用；普通成员返回 `PERMISSION_DENIED`。成功后只为房间内人类成员写 `source = all` 提及与个人提醒，发送者自己除外，不批量创建 Agent 工作，也不批量生成 delivery。

### 3. 删除隐式投递（修正）

- 删除“上一位 Agent 发言后，新消息自动投给相邻 Agent”的服务端推断（原 `resolveAdjacentAgentSender` 路径），普通群回复不再自动唤醒任何 Agent。
- 删除上传脚本自动追加 `@WeBots 维护员` 的行为；附件发送与普通消息一样，只有显式 `invoke` 才派活。
- direct 房间不再由服务端自动把消息投给对端 Agent：网页对 direct 显式把对方 Agent 填入 `invoke`，MCP/CLI 调用方必须显式指定。服务端在 direct 中省略 `invoke` 时不解析正文。
- `scripts/lib/auto-deliver-acceptance.ts` 由 `scripts/lib/no-implicit-delivery-acceptance.ts` 取代，断言方向从“自动投递存在”反转为“这些路径都不创建 delivery”。

### 4. Web 选择器保存 actor_id（修正 + 新增）

- `src/web/chat-script.ts` 的 `mentionSelections` 按房间保存 `{ actor_id, name, kind }`；插入 `@名字` 只负责显示。提交时 Agent 目标进入 `invoke`，人类目标进入 `mentions`；同名成员在选择器中显示为两个独立项，各自写入不同 `actor_id`。
- 提交前 `resolvedMentionSelection()` 用当前 `members` 复核每个选择：成员已移除或改名时提示“所选成员已不在房间，请重新选择”，不发送；正文里已删掉对应 `@名字` 的选择被丢弃，同名 token 按出现顺序、最长名字优先消费。
- `src/web/chat-outbox-script.ts` 持久化 `mentions` 与 `invoke_explicit`；`outboxInvokeKey` 区分“省略 invoke”“显式空 invoke”与“有目标 invoke”，重试/对账复用同一意图。提交成功后只清空当前房间且正文仍匹配的输入框，不再覆盖用户新编辑。
- 群信息复制（`src/web/chat-group-copy-script.ts`）改为逐成员列出 `actor_id`，说明 Agent 进 `invoke`、人类进 `mentions`、`invoke: []` 关闭派活与正文兜底规则；`chat-stream-script.ts` 收到 `mention.reminder` 时提示并刷新列表。

### 5. 契约、CLI 与文档同步（修正）

- `src/contracts/schemas.ts`、`src/mcp/outputs.ts`、`src/mcp/tools.ts`、`src/mcp/skill.ts` 同步 `mentions` 与提及视图；技能正文、`public/skills/agent-network-skills.md`、三份 harness 说明与 `docs/code-index.md` 改为“显式 actor_id 派活/提醒”，删除旧隐式投递描述。
- `public/skills/agentnet.sh` 的 `send` 与 `send-file` 新增 `--invoke <actor_id>`、`--no-invoke`、`--mention <actor_id>`，可组合；参数缺失或未知选项保持非零退出。
- `src/contracts/limits.ts` 未新增阈值，继续使用 `invokeMax = 8`、root delivery 32、协作深度 4；Web、MCP、CLI 共用同一限制与错误文案。

- 错误：显式 `mentions` 指向 Agent、非成员、发送者自己或超过 8 个返回 `INVALID_ARGUMENT`；同名正文解析与超过 8 个正文目标返回 `INVALID_ARGUMENT`；越权 `@所有人` 返回 `PERMISSION_DENIED`。

## 问题与限制

1. **正文兜底是便利输入，不是身份来源**：它只能匹配当前 `active` 成员的精确显示名，区分大小写，不做模糊匹配、不读备注或群昵称；同名成员必须改用选择器或显式 `actor_id`。显示名可被其他成员修改，因此正文中的 `@名字` 不能作为长期稳定身份。
2. **`@所有人` 的提醒扇出按人类成员数增长**：同一事务内为每个人类成员写一条 `mention_reminder` 事件；大群会产生较多小事件。当前未设置额外成员上限，若后续房间规模显著增大，需要单独评估批量提醒的写入与通知成本。
3. **网页选择按房间保存**：提交成功后清空；用户手动删除 `@名字` 或切换身份/退出登录时会丢弃未提交选择。同名 token 按出现顺序、最长名字优先消费；极端情况下用户重排同名 token 顺序会改变选择与 token 的对应关系，重新选择即可。
4. **服务端不再猜测 direct 接收者**：网页 direct 已显式填对端 Agent；通过 MCP/CLI 在 direct 发送时调用方必须显式传 `invoke`，否则只发普通消息。这是 M03 的确定性要求，不是回归。
5. **本地验收的 presence 配置**：`test:acceptance` 的既有 presence 用例要求服务端与测试进程同时使用短 `AGENT_PRESENCE_*`；未设置时会在“关闭最后一个连接后成员显示离线”等待超时（与 `reports/INTEGRATION.md` 记录一致）。这是运行配置，不是本次代码回归。
6. **未做远端部署验收**：本次只在本机临时库验证，未执行 `db:migrate:remote` 或生产发布；集成验证者需在集成 SHA 上重新迁移并复跑门禁。
7. **旧套件删除**：`scripts/lib/auto-deliver-acceptance.ts` 已移除并由 `no-implicit-delivery-acceptance.ts` 取代；若有下游脚本直接引用旧文件需要同步修改（仓库内引用已清理）。
