## 最终行为与变更

### 1. 提议（`network_task_transfer_propose`）

- 当前负责人、任务创建者或群 owner/管理员可发起；目标必须是房间 active 成员，不能是自己、当前负责人或验收人；调用者、创建者、验收人与目标之间存在任一方向拉黑时返回 `BLOCKED`，不留下提议行。
- 提议只写 `task_transfers` 与 `task_transfer_proposed` room 事件，默认 `LIMITS.taskTransferTtlMs = 24h`；同一任务同时只允许一条 pending（`idx_task_transfers_pending` 部分唯一索引），重复发起返回 `CONFLICT`。
- 提议不改变 `tasks.owner_actor_id`、`current_assignment_id`、`status` 或 `revision`，不创建 delivery、不增加 Agent `pending_count`、不推进 `rooms.head_seq`、不产生未读。pending 期间原负责人责任不变。
- 视图由服务端计算 `effective_status`（过期未处理显示 `expired`）与 caller 相关 `can_accept` / `can_reject` / `can_cancel`；`context_ready` 固定为 `false`，等待 D05 上下文包。

### 2. 接受（`network_task_transfer_accept`）

- 只有目标可接受；校验 pending、未过期、目标为调用者、验收人不能接任自己验收的任务、`expected_revision` 与 `from_assignment_version` CAS，并锁定 `current_assignment_id` 对应的 active assignment。
- 同一事务内：撤销旧 active assignment、生成 `assignment_version = max(现存最大版本 + 1, 旧版本 + 1)` 的新 active assignment、更新 `tasks.owner_actor_id/current_assignment_id/revision`、把提议置 `accepted`、关闭旧 assignment 仍 `pending/claimed` 的 `task_offer`/`task_reminder` delivery（减少 `pending_count` 并写取消事件）、写 `task_transfer_accepted`。
- 并发接受由 task revision guard、transfer pending guard、active assignment guard 与部分唯一索引共同裁决，只有一个成功；失败方返回 `ASSIGNMENT_STALE` / `VERSION_CONFLICT` / `CONFLICT` 并带权威状态。
- 重复接受：同 actor 同 `request_id` 按 operations 重放返回原结果；已接受后使用新 `request_id` 再次接受，只要 `responded_by` 是调用者，返回同一任务与 assignment 视图，不递增 revision/assignment_version、不生成新 assignment 或 delivery。

### 3. 拒绝、取消与过期

- 拒绝仅目标可调用；取消允许提议者、任务创建者、当前负责人或群 owner/管理员。两者都可附 `reason` 供审计，只关闭 pending 提议，不改变任务 owner、assignment、revision 或执行版本。
- 过期是惰性语义：读取按 `effective_status` 显示 `expired`，不写状态；下一次 propose/accept/reject/cancel 会把过期 pending 持久化为 `expired` 并写 `task_transfer_expired`。过期后接受返回 `REQUEST_EXPIRED`。
- `cancelPendingTransfersForTask` 作为 D06 提交成果的公共入口：提交成功时把 pending 提议置 `cancelled`，`invalidated_by: 'submit'`，避免已交付任务被迟到接任。

### 4. 旧负责人与新负责人

- 旧负责人仍可普通聊天、读取任务与使用 delivery；progress/block/resume 与再次 transfer 校验“曾持有 assignment”并返回 `ASSIGNMENT_STALE`，而不是误报 `PERMISSION_DENIED`；错误 details 携带真实负责人。
- 新负责人获得新的 active assignment，可写进度/阻塞/恢复/再次交接；D05 上下文包尚未上线，视图仅返回最小 `context` 与 `context_ready: false`。

### 5. 成员失权与停用

- `roomMembersUpdate` 的 remove、`roomLeave` 与 `disableAgent` 在同一事务内调用 `revokeTaskEligibilityStatements`：把该 actor 在作用域内负责的 `in_progress`/`blocked` 任务置 `blocked`、`blocked_reason = 'owner_lost_eligibility'`、清空 owner 与 `current_assignment_id`，撤销 active assignment，关闭其 pending/claimed 任务投递，并取消该任务的 pending 交接，写 `task_blocked` 事件。
- 停用 Agent 跨其全部 active 房间处理；外部副作用不自动重跑，状态保持“未知”，后续恢复必须重新派发。

### 6. 工具面、事件与网页

- 新增 `network_task_transfer_propose` / `accept` / `reject` / `cancel` / `get` / `list`；`get`/`list` 标记 `readOnlyHint`。任务工具共 18 个；整体工具面在 Drive 与房间文件开启时为 100 个，关闭时为 91 个。
- `task_transfer_proposed/accepted/rejected/cancelled/expired` 在 `src/realtime/stream.ts` 统一投影为 `source: 'task.updated'`、`kind: 'task'`、`attention: 'informational'`，只扇出给 active human；不创建 delivery、不增加 `pending_count`、不推进 `head_seq`、不产生未读。
- `src/web/chat-task-transfer-script.ts` 在任务详情 `#task-transfer-panel` 展示待处理交接、状态徽标、说明、有效期与发起/接任者，提供发起、接受、拒绝、撤回入口；按钮只按服务端 `can_*` 显示。成功后重新读取任务详情、任务概览与房间任务；冲突时刷新权威状态并显示错误。脚本 347 行，拼入既有 `<script>` 共享作用域，未改变既有 DOM id/class。
- `src/mcp/skill.ts` 与 `public/skills/agent-network-skills.md` 同步交接工具、24 小时有效期、接受语义、`ASSIGNMENT_STALE` 与 human-only 事件；生命周期行更新为 D02/D03/D04。`scripts/verify-protocol.ts` 增加工具计数、输入/输出 schema、描述、只读提示与技能正文断言，并注册到 `scripts/acceptance.ts`。

## 问题与限制

1. **D05 上下文包未上线**：新负责人通过 `context_ready: false` 与最小 `context` 接续；完整交接 brief/产物包由 D05 提供。负责人变更本身已可用。
2. **D06 提交未上线**：`cancelPendingTransfersForTask` 已实现并由 D04-UNIT 覆盖，但 `network_task_submit` 尚不存在；旧负责人 `submit` 返回 `ASSIGNMENT_STALE` 的端到端路径需在 D06 接入后补验。
3. **过期是惰性处理**：没有后台扫描器；读取显示 `expired`，状态行在下次写操作时持久化。这避免新增定时任务与锁竞争，但数据库中可能长期保留 `pending` + 已过期行。
4. **网页只显示 pending**：面板默认读取 `network_task_transfer_list` 的 pending 视图，接受后待处理项消失、以负责人变化作为成功反馈；历史需用 `status` 参数或 `transfer_get` 查询。若产品希望面板内展示已接受回执，可在后续增量扩展。
5. **外部副作用未知**：撤销执行资格只处理站内任务、assignment、delivery 与 pending 交接，不声称能停止外部命令；外部系统必须自行幂等/取消或核对状态。
6. **CLI 未扩展**：`public/skills/agent_tasks.sh` 未新增 transfer 子命令；MCP 工具与网页入口已覆盖本任务要求。
7. **全量验收未执行**：按指令只跑 D04 专项、协议与网页验收；集成阶段需在集成 SHA 上重跑必需门禁。
