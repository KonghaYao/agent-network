# UI/UX 审查：移动端与跨端布局（2026-11-11）

## 范围与方法

在独立 worktree 中以真实服务、合成账号与 Chromium 触控视口检查会话列表、聊天、建群、群设置、好友、配对、新 Agent、公告、文件预览、Task Trace、文件面板及网页监控。覆盖 320×400、320×568、320×844、390×600、390×844、768×844、1280×844，并模拟打开面板后从 844px 缩至 400px；既有移动端套件另检查暗色模式、长姓名及桌面右栏。此项是浏览器模拟，不等同于实体 iOS/Android 设备测试。

## 发现与处理

| 优先级 | 原有体验 | 处理 |
| --- | --- | --- |
| 高 | 320/390px 群聊标题仅约 48px 宽，搜索、群操作、文件/网页按钮挤在一行 | 标题与搜索保留第一行，群操作集中于第二行；保留完整标题，避免覆盖与横向滚动 |
| 高 | 320px 群设置双列过窄，成员姓名、搜索与操作空间受挤压 | 手机改为单列、全屏可滚动设置，底部操作留在视口内；桌面保留双列 |
| 中 | 新建群聊为小型居中弹窗，手机键盘/长候选列表可用面积有限 | 手机改为全屏弹窗；候选区独立滚动，底部创建操作稳定可达 |
| 中 | 常用入口与搜索框多为 26–38px，触摸易误点且小字号输入易触发移动浏览器放大 | 将手机会话筛选、搜索、群/好友操作、附件、发送、文件和监控等主要触区扩大至至少 44px，输入字号设为 16px |
| 中 | 网页监控五个工具按钮与地址框同排，320px 地址框几乎无法输入 | 手机地址框独占一排，工具按钮排在下方 |
| 低 | 好友弹窗、文件面板的关闭/表单按钮较小 | 加入触区和安全区域内边距，保留现有桌面布局 |
| 高 | 生成配对二维码后，短屏上的“关闭”落在弹窗滚动区之外，320×400px 时约在 y=663px | 手机配对改全屏布局，二维码与设备列表单独滚动；底部关闭按钮始终留在视口内 |
| 中 | 高屏好友弹窗关闭按钮停在中段，底部留出大片空白；预览关闭按钮仅 35px 高 | 好友内容区占满剩余高度、关闭按钮贴底；文件预览保留可滚动正文并提供 44px 关闭触区及安全区域留白 |

## 验证

- `bun scripts/ux-luna/responsive-layout.ts`：上述七个视口的页面边界、水平溢出、手机触区、群名裁切、各面板可用高度及可见底部操作，以及平板抽屉和桌面右栏。
- `bun scripts/ux-luna/mobile-fixes.ts`：原有九个移动/桌面场景；完整姓名允许一行显示，只断言实际文本未被裁切。
- `bun run test:ux`：包含新增响应式回归；`bun run typecheck` 与 `bun run typecheck:tsc` 校验类型。
- `bun run test:web`：Web 浏览器验收 2415 项通过，包含监控工具栏分行与地址框宽度断言。

后续人工检查建议：在实体手机上验证软键盘弹出与系统安全区域，尤其是超长群名和横屏；当前自动化没有物理设备结果。
