## 边界与数据流

客户端 → `POST /mcp` → `src/app.ts` → 官方 MCP TS SDK（仅 `2026-07-28`）→ `src/mcp/tools.ts` / `resources.ts` / `room-files.ts` → `src/domain/` → SQLite。文件上传 → `POST /mcp-upload` → MCPP Files v1 → FlyDrive；房间文件元数据写入 SQLite `room_files`，公开下载统一走 `GET /f/:fileId`（HEAD/Range/304/`?download=1`）。浏览器 → `GET /a/:sessionId` → `src/storage/queries.ts` 按 session 查 actor → `src/web/share.ts` 渲染分享页；建联后跳转 `GET /c/:roomId`。`GET /` 与 `GET /c/:roomId` 都由 `src/web/chat.ts` 的 `renderAppPage` 渲染同一套微信风双栏外壳：左侧 280–320px 会话栏（搜索、64px 会话项、群聊 2×2 头像、未读红点、底部用户/扫码），右侧空状态或聊天区（时间胶囊、左右气泡、36px 头像、群聊发送者、@ 高亮、回执）；桌面打开文件或监控面板时，聊天区与右栏默认 50/50，可拖动分隔条调整并记住比例，关闭面板后聊天占满；移动端按 `<body>` 的 `page-home` / `page-room` 切为单栏。首页由 `share.ts` 的 `renderHomePage` 委托。页面内联脚本用浏览器 token 调用同一 `/mcp`；`GET /` 无 token 时列表区只显示引导，页面不再提供“服务信息”折叠区。

房间任务：领域逻辑在 `src/domain/tasks.ts`，工具注册在 `src/mcp/tools.ts`，表在 `migrations/0010_room_tasks.sql`；写操作走 `runIdempotent`，状态/权限闸门为 `guard_task_conflict`、`guard_task_editor`、`guard_room_task_limit`。任务变更写 room scope `room_task_*` 事件与 `room:<id>` outbox，由 `src/realtime/stream.ts` 映射为 `source='room.tasks'` / `kind='tasks'` 且只扇出给 active human；不写 inbox、不改变 `head_seq`/`last_message_id`/`pending_count`。`network_task_summary` 每房间返回 `pending`/`claimed`/`done`/`failed`/`total`，`claimed` 只统计当前身份领取；`login.task_summary` 是 active 房间聚合，同样只把本人 claimed 计入。网页头部任务行、浮层与侧栏 badge 在 `src/web/chat-tasks-script.ts`，侧栏汇总由 `chat-list-script.ts` 在列表刷新时一次调用 `network_task_summary`，任务事件在 `chat-stream-script.ts` 中刷新当前房间和 badge；静态命令脚本为 `public/skills/agent_tasks.sh`。

群角色与管理员权限（G03）：`migrations/0020_group_roles.sql` 把 `room_members.role` 扩展为 `owner`/`admin`/`member`，增加 `role_revision`/`updated_at`，以部分唯一索引保证每房间至多一个 active owner，并保留 `rooms.owner_id` 作为同事务同步的当前 owner；`rooms` 增加 `policy_revision`、`member_message_policy`/`member_invite_policy`/`member_task_policy`（`members` 或 `owner_admin`）与公告字段、`announcement_revision`；`room_management_audit` 追加记录成员、角色、owner 转移、策略与公告变更，角色/策略/公告版本闸门为 `guard_role_revision`/`guard_policy_revision`/`guard_announcement_revision`。`src/domain/room-access.ts` 是群内授权的唯一来源，导出能力表、成员动作、预检与事务 guard；`network_room_members_update` 按 `invite_members`/`remove_members` 与目标 `actions.can_remove` 判定，新增 `network_room_role_set`、`network_room_owner_transfer`、`network_room_policy_set`、`network_room_announcement_set`、`network_room_role_history`。消息与建任务入口也复用同一能力谓词；群角色不写入 `agent_managements`，不授予 Agent 所有权或凭据权限。网页成员弹窗显示群主/管理员/成员并按 `member.actions` 展示任免、转移与移除，公告条与弹窗只对 owner/管理员可编辑；`room_role_changed`、`owner_transferred`、`room_policy_changed`、`room_announcement_updated` 统一映射为 `room.membership` informational 项刷新视图。

手机扫码：`src/web/handoff.ts` 在左下角用户区块提供入口，`src/web/qr.ts` 在 canvas 现场编码 `location.origin + '/#t=' + encodeURIComponent(token)`；不请求服务端、不新增工具或路由。弹窗的“复制扫码内容”复制同一 URL，优先 `navigator.clipboard.writeText`，失败回退临时 `textarea` + `execCommand`；无 token 时禁用，token 不进入页面文本、DOM 或 console。手机打开后，早执行的 `HANDOFF_ADOPT_SCRIPT` 读取 `#t=`、写入 `localStorage['agent-network-token']`、用 `history.replaceState` 清除 hash，首页脚本随后读取同一 token，因此手机与桌面是同一 actor、同一权限。token 位于 fragment，不随文档请求发送；但二维码本身即长期凭据，弹窗与文档必须提示勿截图/分享，且不声称过期、一次性或“已扫码”。

退出登录：`src/web/chat-logout-script.ts` 在主脚本共享作用域内提供 `#logout` 图标与 `#logout-modal` 确认弹窗；入口只在有 token 时显示，带 `aria-label`/`title`“退出登录”，默认聚焦“取消”，支持 Esc/遮罩关闭、暗色与 390px。确认后只删除本机 `localStorage['agent-network-token']` 与 `localStorage['agent-network-agents-v1']`（`agent-network-files-open` 等 UI 偏好保留），删除 `agent-network-*` sessionStorage 状态，调用 `stopActorStream()` 断开 SSE/重连/补读定时器，然后 `location.replace('/')`；不调用服务端、不吊销 token。退出后首页读取非敏感 `localStorage['agent-network-logged-out']`，不自动注册新身份、不建 SSE，列表与桌面空状态显示分享链接/连接提示词引导及“创建新身份并继续”；点击该按钮、`#t=` 采纳或分享页新建身份时清除标记。弹窗与文档必须写明 token 仍然有效、其他设备不受影响；token 不进入弹窗文本、DOM、console 或测试输出。

应用页按职责拆分：`src/web/chat.ts` 只保留 `renderAppPage` / `renderChatPage` 与外壳组合；样式在 `chat-styles.ts`，静态标记与搜索框在 `chat-panels.ts`，通信/刷新/事件在 `chat-script.ts`，输入框附件按钮、待发送文件 chips 与粘贴图片在 `chat-upload-script.ts`、样式在 `chat-upload-styles.ts`，`+` 附件菜单与画板懒加载桥接在 `chat-drawboard-script.ts`、加载失败样式在 `chat-drawboard-styles.ts`，Fabric 画板在 `src/web/drawboard/entry.ts`、样式在 `src/web/drawboard/styles.ts`、构建在 `src/web/drawboard-bundle.ts`，会话列表、单聊/群聊分类与搜索在 `chat-list-script.ts`，Agent 品牌头像映射与图片回退在 `chat-avatar-script.ts`，退出登录清理与确认弹窗在 `chat-logout-script.ts`，本人姓名编辑在 `chat-account-rename-script.ts`，归档状态、已归档浮层与 toast 在 `chat-archive-script.ts`，群聊头部复制群信息提示词在 `chat-group-copy-script.ts`，消息渲染（时间胶囊、@ 高亮、回执）在 `chat-render-script.ts`。右侧面板分栏由 `src/web/resizer/entry.tsx`（React 岛，`@use-gesture/react`）与 `src/web/chat-resizer-script.ts` 负责，构建在 `src/web/resizer-bundle.ts`，只写 `--right-pane-ratio`，不重建聊天/文件/监控 DOM。Fabric 与画板 UI 只由打开画板时的动态 import 加载，关闭时销毁 canvas、覆盖层、样式与键盘监听；导出白底 PNG File 后走现有 `insertAttachFiles`/chip 上传链路且不自动发送。pending attachments、文件 URL 与自动 `@WeBots 维护员` 按 room 隔离，没有附件时只发送用户文本。列表与渲染片段拼进同一个 `<script>` 共享作用域；拆分不改变工具契约、DOM id/class 或页面行为。所有 `src/web/*.ts` 均低于 `STD-SIZE-001` 的 1000 行上限。

AI 消息 Markdown：`src/web/markdown/entry.tsx` 是唯一的 React 子树（React 19 + `streamdown` 2.7.0，`mode="static"`、`parseIncompleteMarkdown={false}`），只接收 `sender_kind === 'agent'` 的气泡；`src/web/chat-markdown-script.ts` 在首条 AI 消息出现时懒加载 `/assets/chat-markdown.js`（失败只请求一次并保留纯文本），负责 mount/update/destroy 与滚动补偿；样式在 `src/web/chat-markdown-styles.ts`。`src/web/markdown-bundle.ts` 在 `src/bun/main.ts` 启动时用 `Bun.build` 生成单文件浏览器 bundle，`src/app.ts` 以正确 content-type、`nosniff` 与 5 分钟缓存提供；构建失败返回 404。安全配置为 sanitize + harden（`http/https/mailto`、无图片、无 data image、`defaultOrigin=location.origin`），不启用 `rehype-raw`，不内置图片，不使用 `dangerouslySetInnerHTML`；链接强制 `target=_blank`/`rel`/`referrerPolicy`，错误边界回退纯文本。服务端 `network_history_list` 在 `messageSchema` 上增加只读 `sender_kind`，网页优先该字段并回退 `members`；人类消息始终纯文本，512B 截断的 AI 消息展开后再渲染 Markdown。文件卡片仍由正文扫描生成在气泡外，`@名字` 在文本节点内高亮、代码块内不误高亮。

通知：domain 在业务事务内写 `events` 与 `outbox` → `src/realtime/outbox.ts` 认领并映射事件 → `src/realtime/stream.ts` 生成带 source/attention 的统一 item → `actor:{id}` 扇出 → `src/mcp/stream.ts` 输出 `notifications/resources/updated`（`params.uri = agentnet://stream`，来源在 `params._meta["io.agent-network/event"]`）。SQLite 是权威；hub 不保存业务历史。`room:{id}` / `inbox:{actor}` 只是 outbox 内部写分区键。`network_login` 门控整个 Agent stream（含房间消息）；未上线或断线的 Agent 靠 SQLite 补发，login 返回 `pending_count` 与只读 `task_summary`。

网页发送：`src/web/chat.ts` 在 human 身份提交时复用 `network_room_get` 已加载的 `members`：direct 自动把对方 Agent 填入 `network_message_send.invoke`；group 完全省略 `invoke`，由 `src/domain/messages.ts` 的 `resolveGroupMentionInvoke` 按正文 `@名字` 解析当前 active 成员并只对唯一 Agent 成员创建 delivery。用户在群聊未 @、未显式 invoke 时，`resolveAdjacentAgentSender` 按 `created_seq` 倒序读取紧邻上一条 `messages`，若其发送者仍是 active Agent 成员则自动投递（仅 human 发送；direct、Agent 发送、带 `claim` 的回复不触发；上一条 human/无消息/已移除成员不投递）。显式 `invoke`（含 `[]`）与正文 @ 任一 active 成员名（含用户/自己）优先，不会追加或误投上一条 Agent；未匹配成员的 `@xxx` 不阻断自动。解析按名字长度降序、精确、大小写敏感、原文匹配，不 trim/不归一化；非 Agent 成员与发送者参与最长匹配但不投递，非成员名字只是普通文本；同名 Agent 返回 `INVALID_ARGUMENT`，超过 `LIMITS.invokeMax` 沿用现有错误。direct、带 `claim` 的回复与 `final_body` 不解析。页面不再本地记录 `mentionTargets` 或复制上限；Agent 的工具调用/普通回复仍是 `invoke: []`。

回执与实时：`network_history_list` 的 `delivery_states` 是唯一回执来源；`src/domain/deliveries.ts` 在 claim/report/complete/fail/cancel/retry 的同一事务内写 room scope 事件与 `room:{id}` 内部 outbox，发送方页面的统一流收到 `delivery.updated` 后走串行 `refresh()`。claim/report/complete/fail 仍写 inbox 事件维护 `pending_count` 与 sync，但不推回 recipient 自己。回执事件不推进 `rooms.head_seq`，因此不会产生“没有新消息”的未读点。`messages.ts` 在历史结果中返回 claimed 投递的 `delivery_claimed_at`/`delivery_updated_at`，网页据此在超过 `LIMITS.claimedStaleMs` 时提示“处理中未更新”。

投递提醒：`src/domain/delivery-reminders.ts` 每 `LIMITS.deliveryReminderScanMs`（30 秒）扫描 `state='claimed'` 且 `progress_at <= now - LIMITS.deliveryReminderMs`（3 分钟）的投递，按 `last_reminded_at` 去重并每 3 分钟重复。`migrations/0011_delivery_reminders.sql` 增加可空 `last_reminded_at` 与 `idx_deliveries_claimed_progress` 部分索引；claim/report/retry 清空该列。扫描在同一个 `db.batch()` 中条件更新 `last_reminded_at`、插入 inbox scope `delivery_reminder` 事件、写 `inbox:{actor}` outbox，并经 `inboxHeadStatementIfEvent` 以 delta=0 推进 inbox head；事件与 outbox 都要求 `last_reminded_at = now`，只有赢得本次提醒窗口的扫描才写入，不同毫秒的并发扫描收敛为一次提醒，同毫秒并发由 event_key 唯一约束收敛，重启窗口由持久化的 `last_reminded_at` 去重。提醒不创建 delivery、不改变 `pending_count`、不推进房间 head、不写 room scope 事件或 `room:{id}` outbox，也不更新 `deliveries.updated_at`。`src/realtime/stream.ts` 映射为 `source='delivery.reminder'` / `kind='reminder'` / `attention='action_required'`；`network_sync { scope: 'inbox' }` 可读取。监听脚本的提醒分支在 `peri-watch.sh`、`claude-watch.sh`、`codex-watch.sh`，`other-sentinel.sh` 仍按 `^ALERT` 计数。

房间文件：`src/domain/room-files.ts` 负责 bind/list/get/delete、成员与上传者/群 owner 权限、每房间 200 个 / 1 GiB 配额、最长 30 天 TTL（`min(now + 30d, upload.expires_at)`）、删除墓碑与 `PUBLIC_ORIGIN + /f/<file_id>` 派生；`src/mcp/room-files.ts` 在 MCPP Files 挂载时注册 4 个工具，bind 只接受当前身份且未过期的 `fileId`，同一 `file_id` 只能属于一个房间。`src/app.ts` 的 `/f/:fileId` 提供无 Bearer 下载，`src/drive/service.ts` 的 `publicFileHeaders` 负责 HEAD/Range/ETag/P0 安全头，`purgeFilePayloads` 在墓碑提交后 best-effort 回收载荷。`src/realtime/stream.ts` 把 `room_file_added` / `room_file_deleted` 映射为 `source: "room.file"`、`kind: "file"` 的 informational item，不创建 delivery、不增加 `pending_count`、不推进 `rooms.head_seq`。网页文件栏为 `>= 1200px` 右侧第三栏（与聊天区默认 50/50，可拖拽并记住比例）、`760–1199px` 抽屉、`< 760px` 全屏；输入框左侧“+”与粘贴图片复用同一条上传/bind/插入链路，插入草稿后不自动发送；SVG/HTML 不内联预览，复制 URL 提示公开链接即下载权限；三档布局、真实上传/bind/预览/删除、拖拽比例与 `room.file` 刷新由 `bun run test:web` 1226 项覆盖（含 AI Markdown、气泡宽度、扫码复制、网页监控与 390px）。

网页监控：`migrations/0008_actor_room_monitors.sql` 新增 `actor_room_monitors(actor_id, room_id, url, created_at, updated_at)`，主键 `(actor_id, room_id)`，`url <> ''`，清除删除行。`src/domain/room-monitors.ts` 做 human-only、active 成员、http/https 与 2048 字节上限校验，`set` 走 `runIdempotent`（operations → `guard_not_member` → UPSERT/DELETE），不写 events/outbox，不改变 head/未读/pending，错误不回显 URL。工具 `network_room_monitor_get/set` 只按当前 principal + room 读写，没有 actor_id 参数；Agent 调用返回 `INVALID_ARGUMENT`。网页由 `src/web/chat-monitor-script.ts` / `chat-monitor-styles.ts` 实现独立右侧面板（与文件面板共用分隔条，桌面默认 50/50、可拖拽调整，平板抽屉、移动全屏），与 `files-pane` 互斥；顶部单行图标工具栏包含标题、地址框与保存/清除/新标签页/刷新/关闭，iframe `flex:1` 填满剩余高度；iframe 无 sandbox，URL 只用 DOM `src`，关闭/切房/回首页置 `about:blank`，打开/切房/手动刷新时才 get，不轮询；URL 不写 localStorage、console 或 SSR HTML。
